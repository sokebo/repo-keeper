# repo-keeper

> **占位名，随时改。**
>
> 对 GitHub 仓库做整套建模，让用户看清**自己到底做了什么**、**这些事怎么串起来**。
>
> 类比：**仓库管理员** —— 替仓库主理清全貌。

**状态**：产品定位已定，第一版未实现。读 [第七节](#七当前进度) 知道现在能做什么、不能做什么。

---

## 一、四步目标（顺序不可换）

1. **先把底层的图推理能力验证扎实**
2. **解决自己的痛点**
3. **开源，开始积攒 star**
4. **解决其他人的痛点**

第 1 步排在第 4 步之前：**先自己用起来、把发动机验证了，再谈服务别人。**

跳过第 1 步直接开源，等于让别人来当验证场 —— 这是绝大多数个人项目的死法。

## 二、它解决什么痛点

痛点已经被观察证实，不是推演：

> 团队述职前要做 PPT，大家开始用 AI 工具去仓库"猛猛拉"自己过去的工作内容。

这个现象说明三件事：

1. **痛点真实** —— 每年都要做，躲不掉
2. **现在靠 AI 硬扛** —— 慢、每次说法不一样、隐私出本机、下次从零重来
3. **有捷径的人是"懒"** —— 自己手动找太花时间。连作者本人都���选择用 AI

## 三、它不是什么（防跑偏用）

| 不是 | 因为 |
|---|---|
| GitHub 数据导出器 | commit→PR、PR→issue、milestone 这些 GitHub 原生就有，不重复造 |
| **述职工具** | 述职是最容易感知到痛的时刻，但**不是产品定义**。把入口当定位会做歪 |
| 图可视化工具 | **图是中间产物**。GitHub 贡献热力图就是最好的反例：全球知名，但没人为它装工具 |
| 取代 AI 的东西 | **连作者本人都会绕过它去用 AI**。定位成"替代 AI"从第一天就输了 |

## 四、节点与边

### GitHub 原生就有（不重复造）

- commit → branch → PR
- PR → issue（closing keywords `fixes #123`）
- issue → milestone / label / project
- review 关系、共同 reviewer

### 要算的（三类）

1. **commit / PR ↔ 决策文档**
   GitHub 只索引 commit message、PR 描述、issue 正文，**不索引仓库里的 markdown**。
   `notes/01-decisions/决策日志.md` 这类文件在 GitHub 上一条都搜不到。

2. **issue ↔ issue 是否同一话题**

3. **PR ↔ PR 是否同一主线**

## 五、查询清单（管理员视角）

| 问题 | 直接问 AI 能不能给 | 为什么 |
|---|---|---|
| 我最近在忙什么 | 能，但每次说法不一样 | 无状态 |
| 这些事怎么串起来 | 部分能 | 无状态 |
| **哪些 issue / PR 挂着没人管** | ❌ | 不知道历史 |
| **哪些分支僵尸了** | ❌ | 不知道上次跑到哪 |
| **有没有重复 issue** | ❌ | 要全库对比，不是问一句 |
| **决策落档了但没落地** | ❌ | 文档和 commit 之间的对应关系得有人接 |

**后四类全都需要一套持续维护的模型。** 这就是"建模"而不是"生成报告"的原因——
**报告是一次性的，建模是长期的。**

## 六、形态主张

- **本地跑。** 数据不出本机。边界怎么划见 [PRIVACY.md](./PRIVACY.md)。
- **复用 `gh auth login`**（device flow，**不需要自建 OAuth 服务器**）。`gh` CLI 已经有了。
- **可查，不只出报告。** 建模如果不能查，就只是一堆数据。

  跑一遍就知道你的仓库在下面几项上是什么水平。**这是目前唯一的可用工具。**

## 八、已知的 gap

第一版会为"自己的仓库"设计，通用化天花板摆在前面：

- 有决策日志的仓库 → 值得建模；随手 commit 的仓库 → **模型塌成单层，价值减半**
- 有编号规范（RFC-xxx / ADR-0007）的仓库 → 关联可以精确；没有的 → 只能靠语义猜

撞上这个 gap 有两条路：**加抽象层兼容**，或**明说"第一版只支持有留档习惯的仓库"**。
倾向后者 —— 前者就是通用化，而通用化有天花板。

## 九、诚实边界

- 第二节的痛点**有实测观察**（团队确实在用 AI 拉），但**没有统计过多少人真的痛**
- 这类工具品类不空（GitHub Insights / Sourcegraph / 各类 commit 摘要插件）
- **差异化不在"拉数据"，在第五节后四类** —— 那些是跨时间问题，无状态的对话式工具答不了
- 第七节的实测语料是**一组以私有仓为主的真实仓库**，全部数据本地处理、未上传。
  仓库名、组织名、账号名、内部路径一律不公开；只公开方法论与聚合结果。
